# qwen3-tts-1-7b-voiceover

> 专用于 Qwen3-TTS 1.7B Base 的口播稿优化 —— 逐字保真，只调标点与结构。

把书面稿优化成专供 Qwen3-TTS 1.7B Base 朗读的口播稿。与面向高参数模型、依赖人工挑句的「去 AI 味」方案相反：本方案承认该模型念不准语气词与标注，因此在实测能力边界内做减法——**只插标点、不改字、绕开会出戏的表达**。所有判据都来自该模型实测，换模型或换版本需要重新标定。

## 它做什么

- **只做文字稿**：不生成音频、不调用 TTS、不改文章观点与结构。
- **两层分工**：L1（`scripts/tts/rewrite.py`）做结构编辑（钩子前置、文体分流、口述体硬处理）；L2（`scripts/tts/humanize.py`）做标点拟人化（逐字保真、只插停顿）。
- **带校验自愈**：fidelity / 句尾语气词 / 润色不足 / 篇幅超限不合规时，自动带 hint 重问 LLM。

## 核心约束（为什么这样做）

Qwen3-TTS 1.7B Base 的实测特性决定方案形态，不是风格偏好：

| 该模型特性 | 方案对策 |
|---|---|
| 语气词会念成实读音 | 严禁新增，原文自带的保留 |
| 填充词（嗯/呃/就是说）念成实读音 | 一律不插，停顿只用 …… |
| 破折号读不出稳定停顿 | 改成逗号或句号 |
| 不认段级语速/情感标注 | 标注逻辑默认关闭 |
| 数字按基数词误读年份 | 年份逐位读，且必须先于 fidelity 基线 |

## 与 kaikou 的关系

kaikou 是面向高参数模型 + 人工精修的方案（先配音再听、一句配 4 遍挑句、加语气词）。本方案是它的反面：流程不依赖人工、文本规则大多已覆盖对方条目、成本固定。详细结论见 `SKILL.md` 的「与 kaikou 的结论性对比」。

## 使用方式

在 WorkBuddy 中，当任务涉及 Qwen3-TTS 1.7B Base 的口播稿准备、配音稿拟人化、配音出戏排查时，skill 会被自动加载；也可直接阅读 `SKILL.md` 获取完整规则。
